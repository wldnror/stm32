STM32 debug appliance 3.76

Normal firmware/folder menus show the clock as HH시 MM분 again, within a
64-pixel area before the Wi-Fi bars. System/Wi-Fi menus retain their compact
clock because their status row also contains the brand and version.

Entry: main.py -> serve.py. systemd owns restart/recovery.
UI: display_manager.py (128x64 OLED), menu_manager.py, app_state.py.
Hardware: stm32_manager.py (OpenOCD/GPIO), modbus_manager.py (LAN/TFTP), power_manager.py.
Networking: wifi_backend.py (NetworkManager), wifi_portal.py (setup HTTP),
network_utils.py (link/address parsing), process_utils.py (bounded process groups).

Wi-Fi setup
- Hold the Wi-Fi setup menu item. Join GDSENG-SETUP using the password shown on the OLED.
- Open http://192.168.4.1:8080 (port is shared with the OLED configuration).
- Choose a scanned SSID or manually enter a hidden SSID. Password whitespace is preserved.
- Association + an IPv4 address counts as connected; external internet is optional.
- The Pi has one radio: the setup AP disappears while connecting to the target Wi-Fi.
  Rejoin the setup AP if connection fails. Cancellation/timeout restores the previous profile.
- The setup AP is owned by NetworkManager (shared IPv4 requires dnsmasq-base).
  Do not run separate hostapd/dnsmasq/wpa_supplicant instances on wlan0.
- Setup HTTP binds only to the AP address and changes are rejected outside setup mode.
- The last working profile UUID is stored under ~/.config/stm32/ for crash recovery.

Updates
- git-pull.sh updates the current tracking branch, using fast-forward only.
- A failed fetch or tracked local modification is an error, never success.
- Initial startup does not install packages or wait on apt/network access.
- Install the Python/hardware dependencies during provisioning. Preserve the known-working
  pymodbus API version (slave=1); do not replace it with a new incompatible major version.
- deploy/stm32.service documents the tested service configuration.

Firmware extraction
- Extracted files are saved under Download/ before FTP transfer.
- FTP credentials are read from ~/.config/stm32/ftp.json (chmod 600), keys:
  server, username, password, path. STM32_FTP_PASSWORD overrides the password.
- No credentials are stored in this repository. Failure to upload returns nonzero
  and preserves the local extracted file. No firmware writes are part of unit tests.

Verification
python3 -m unittest discover -s tests -v
TEST_FONT may point to the installed OLED TrueType font for exact metrics.
Tests use fake GPIO/OLED hardware; real AP/client transitions require a separate
recovery timer so the device can restore Wi-Fi independently of an SSH session.

Early startup screen (3.75)
- Install BOTH deploy/stm32.service and deploy/stm32-boot-screen.service into
  /etc/systemd/system/, daemon-reload, and enable both units.
- The boot-screen unit starts during sysinit with no networking dependency.
  It loads the installed I2C drivers and draws via Python standard-library I2C,
  before the main app imports its fonts, web server or hardware modules.
- Main app startup also no longer waits for network.target. It publishes real
  milestones to /run/stm32-boot/state.json; the bar never completes by a timer.
- An exclusive lock hands the OLED from the splash to the normal display.
  The splash closes its bus without clearing the screen.
- systemd READY=1 is sent only after a real menu frame has been transmitted.
- The menu journal and /run/stm32-boot.log record timestamps since Linux
  kernel start, excluding the Raspberry Pi firmware interval before Linux.
  The early service logs directly under /run so it can start
  before the journal socket. Its initial priority is lowered after the first frame.
- A legacy installation without the early unit still starts the normal app.

- Flask and the web setup UI are loaded only when Wi-Fi setup is requested.
  Normal menu startup and connectivity polling do not import the web server.
- A separate 100 Hz button sampler applies 40 ms stable-state debounce to both
  buttons, including a button held during startup. It uses direct GPIO reads
  instead of sysfs edge registration, which failed during early udev startup.
  Release, long-press and cancellation behavior still use the existing handlers.
- /run/stm32-boot/first-frame.json retains the first successful OLED write time
  even if journald was not running yet. state.json at READY records menu time.
  startup-error.log in that directory retains an early application traceback.

On-device validation (Pi Zero W, 2026-10-19)
- Final reboot: first splash frame at 19.492 s, first real menu frame at
  35.664 s after Linux kernel start; no application restart or failed unit.
- A preceding reboot also reached the menu without restarting (36.071 s).
- 47 regression tests pass locally and on the Pi. They include SH1107 packing,
  exclusive handoff, readiness notification, button bounce and press/release.
- These measurements do not include pre-kernel firmware initialization and
  are not a promise of a fixed power-on time on other SD cards or hardware.
